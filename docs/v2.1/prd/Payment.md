# [PRD] 결제 모듈 (Payment)

## 1. 개요 (Overview)
본 문서는 쇼핑몰 SaaS의 결제 모듈에 대한 PRD입니다. 
주문서 작성 완료 후 외부 결제 대행사(PG)를 통한 안전한 결제 승인, 금액 위변조 검증, 주문 상태 자동 연동, 취소 및 부분/전액 환불, 영수증 조회 기능을 제공하는 것을 목표로 합니다.

---

## 2. 관리 데이터 범위 (Data Scope)

### 2.1 결제 트랜잭션 데이터 (Payment Transaction)
- **결제 식별자**: Payment ID (고유 결제 ID), Order ID (주문 매핑 ID), User ID (구매자 ID)
- **PG 연동 정보**: PG사 식별자 (TID / 거래번호), 결제 수단 (`신용카드`, `계좌이체`, `가상계좌`, `카카오페이`, `네이버페이` 등)
- **금액 및 상태**: 최종 결제 승인 금액, 결제 상태 (`결제대기`, `결제완료`, `결제실패`, `취소진행중`, `취소완료`)

### 2.2 환불 데이터 (Refund Data)
- **환불 식별자**: Refund ID, PG 취소 거래번호 (Cancel TID)
- **환불 상세**: 환불 유형 (`전액환불`, `부분환불`), 환불 요청 금액, 환불 사유, 환불 완료 일시

---

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 결제 최종 확인 (Client UI)
- **주문 요약 제공**: 결제 진행 직전 구매 상품 목록, 최종 결제 금액(상품가 + 배송비 - 할인금액), 배송지/픽업 정보, 선택한 결제 수단을 한 화면에서 일괄 확인
- **결제 동의 및 시점 제어**: 필수 약관 동의 후 '결제하기' 버튼 클릭 시 PG 결제 창으로 전환

### 3.2 외부 결제 대행사(PG) 연동 및 모듈 호출 (System & Client)
- **다양한 결제 수단 지원**: PG사 SDK/API를 통해 신용카드, 실시간 계좌이체, 가상계좌, 간편결제(카카오페이/네이버페이/토스페이 등) 모듈 호출
- **결제 요청 데이터 전달**: PG사로 주문 ID, 결제 금액, 상품명, 구매자 정보를 표준화된 규격으로 전송

### 3.3 결제 승인 및 주문 상태 연동 (System Engine)
- **금액 위변조 검증 (Validation)**: PG 승인 결과 수신 시, DB의 주문서 실 결제 예정 금액과 PG 승인 요청 금액이 정확히 일치하는지 백엔드 상에서 재검증
- **결제 완료 처리**: 검증 성공 시 결제 상태를 `[결제완료]`로 업데이트하고, `주문 모듈`에 이벤트를 발행하여 주문 상태를 `[주문접수]`로 즉시 전환
- **결제 실패 처리**: 카드 한도 초과, 인증 실패 등 실패 발생 시 PG 에러 메시지를 소비자 화면에 노출하고 결제 재시도 유도

### 3.4 결제 취소 및 환불 처리 (Admin & Client)
- **전액/부분 환불 요청**: 배송 전 취소 승인 또는 반품 확정 시, 사업자/시스템 요청으로 외부 PG사 취소 API 연동
- **차등 환불 지원**: 단순 변심 반품 시 왕복 배송비 차감 후 '부분 환불' 처리 로직 지원
- **가상계좌 환불**: 가상계좌 결제 건 취소 시 소비자가 입력한 환불 계좌(은행, 계좌번호, 예금주)로 환불 API 호출 또는 입금 처리

### 3.5 결제 및 환불 내역/영수증 조회 (Admin & Client)
- **소비자 조회 (Client App/Web)**: 마이페이지 주문 상세 내역에서 승인된 결제 수단, 결제 일시, PG 매출전표(신용카드 영수증) 및 현금영수증 확인/출력
- **사업자/관리자 조회 (Admin Web)**: 
  - 어드민 내 결제/환불 관리 대시보드에서 PG 거래번호(TID) 기준 검색 및 상태 추적
  - 승인 내역, 취소 내역, PG 정산 예정 데이터 조회

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **보안 및 위변조 방지 (Security)**:
  - 모든 결제 관련 통신은 HTTPS 암호화 적용 및 PG Webhook 수신 시 Signature/Hash 검증 필 수행
- **웹훅 멱등성 보장 (Idempotency)**:
  - PG사로부터 동일한 결제 완료 Webhook이 중복 수신되더라도 이중 승인 처리나 중복 주문 상태 변경이 발생하지 않도록 멱등성(Idempotency Key) 보장
- **가상계좌 입금 통보 (Webhook Reliability)**:
  - 가상계좌 입금 완료 통보(PG Webhook) 수신 실패 시 자동 재시도 및 수동 입금 확인 기능 제공
