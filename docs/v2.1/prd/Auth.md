# [PRD] 회원 인증 및 프로필 관리 모듈

## 1. 개요 (Overview)
본 문서는 쇼핑몰 SaaS의 회원 가입, 로그인, 및 최소 프로필 입력 로직에 대한 PRD입니다. 
소셜 로그인(OAuth 2.0) 기반의 써드파티 통합을 통해 진입 장벽을 낮추고, 결제 및 배송에 필요한 최소한의 추가 정보만 수집하여 이탈률을 최적화하는 것을 목표로 합니다.

---

## 2. 사용자 정보 수집 범위 (Data Scope)

### 2.1 SNS 소셜 로그인 수집 정보 (기본 제공)
- **식별자**: Unique User ID (Supabase Auth UID)
- **기본 프로필**: 이메일, 이름

### 2.2 추가 입력 정보 (로그인 후 / 배송 정보)
- **수령인 이름**: 필수
- **연락처**: 필수 (휴대폰 번호)
- **기본 배송지**: 필수 (우편번호, 기본 주소, 상세 주소)

> **[혜택 및 마케팅 로직 포함 여부 판단]**  
> 신규 가입 혜택(쿠폰/포인트 지급 등)은 회원가입 완료 이벤트와 연동되므로 본 PRD의 **`3.3 후속 처리 로직`** 섹션에 **이벤트 연동 명세** 형태로 포함합니다. 상세한 쿠폰/포인트 발행 규칙은 '혜택/프로모션 PRD'에서 다룹니다.

## 3. 기능 요구사항 (Functional Requirements)


## 3.0 사용자 이용 흐름 (User Flow)

1. [진입] 유저가 쇼핑몰 회원가입/로그인 페이지에 접근
2. [인증] 원하는 SNS 버튼(Google, Instagram, Naver, Kakao) 클릭 후 OAuth 인증 진행
3. [분기] 인증 완료 후 서비스 DB 조회
   - Case A. 기존 회원 (추가 정보 작성 완료) -> 메인/이전 페이지로 이동 (로그인 완료)
   - Case B. 신규 회원 또는 추가 정보 미입력 회원 -> '추가 정보 입력(배송지 등)' 페이지로 이동
4. [정보 입력] 수령인 이름, 연락처, 배송지 주소 입력 후 완료 버튼 클릭
5. [완료 및 혜택] 
   - `profiles` 테이블에 유저 정보 저장
   - `USER_REGISTERED` 이벤트 발생 -> 신규 가입 혜택(쿠폰/포인트) 자동 지급
   - 메인 화면으로 리다이렉트

### 3.1 Front-End (FE)
- **SNS 로그인 UI**:
  - 기존 자체 이메일/비밀번호 회원가입 연동 UI를 제외하고, SNS 로그인 버튼만 배치
  - 지원 플랫폼: Google, Instagram, Naver, Kakao
- **추가 정보 입력 UI (온보딩 페이지)**:
  - 소셜 로그인 성공 후, 필수 추가 정보(배송지, 연락처) 미입력 유저인 경우 추가 정보 입력 화면으로 강제 리다이렉트
  - 주소 검색 API(예: 카카오 우편번호 서비스) 연동

### 3.2 Back-End (BE) & 인프라 (Supabase + Google Cloud)
- **인증 방식**:
  - Supabase Auth를 통한 OAuth 2.0 써드파티 통합 (Google, Instagram, Naver, Kakao)
  - Google Cloud 인프라와의 연동을 통한 보안 및 토큰 검증
- **토큰 기반 세션 관리**:
  - 인증 성공 시 Supabase에서 발급한 JWT(Access/Refresh Token)를 사용하여 모든 API 요청의 인가(Authorization) 처리
- **데이터베이스 (DB)**:
  - `auth.users` 테이블과 연동되는 `profiles` 테이블 구성 (추가 정보 및 배송지 저장)

### 3.3 후속 처리 로직 (가입 혜택 연동)
- **가입 완료 이벤트 발행**:
  - 추가 정보(배송 정보 등) 입력이 완료되면 `USER_REGISTERED` 이벤트를 발생시킵니다.
  - 해당 이벤트를 구독하는 혜택 모듈에서 신규 가입 쿠폰 및 포인트를 자동 지급합니다.

### 3.4 약관 동의 및 개인정보 보호 (Compliance)
- **약관 동의 프로세스**:
  - 소셜 로그인 성공 후 추가 정보 입력(온보딩) 화면에서 약관 동의 진행
  - [필수] 서비스 이용약관 동의
  - [필수] 개인정보 수집 및 이용 동의
  - [선택] 마케팅 활용 및 혜택 알림 동의

### 3.5 로그아웃 및 회원 탈퇴 (Account Lifecycle)
- **로그아웃**:
  - 클라이언트 세션 클리어 및 Supabase Auth `signOut()` 호출을 통한 토큰 무효화
- **회원 탈퇴**:
  - 탈퇴 요청 시 유저 프로필 데이터 파기 또는 익명화 처리
  - 관련 법령(전자상거래법 등)에 따라 주문/결제 데이터는 5년간 별도 분리 보관

### 3.6 예외 처리 및 계정 통합 정책 (Edge Cases)
- **이메일 중복 (동일 계정 소셜 로그인)**:
  - 동일한 이메일 주소로 다른 소셜 제공자 로그인 시도 시 Supabase Identity Linking 정책 적용
- **온보딩 이탈자 접근 제어 (Route Guard)**:
  - `profiles`에 필수 배송지 정보가 없는 유저는 결제 및 회원 전용 페이지 접근 불가 (온보딩 페이지로 강제 리다이렉트)
- **OAuth 인증 취소/실패**:
  - 사용자가 소셜 로그인 동의 창을 닫거나 실패 시 "로그인이 취소되었습니다." 안내 레이어 제공 후 로그인 페이지 유지
---

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **보안 & 개인정보**:
  - 전화번호 및 주소 정보는 암호화 전송(HTTPS) 및 Supabase RLS(Row Level Security)를 통한 접근 제어
- **사용성 (UX)**:
  - 소셜 로그인 후 추가 정보 입력 완료까지 3단계 이내로 완료 가능한 간결한 동선 제공
