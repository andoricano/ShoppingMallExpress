# [PRD] 주문 관리 모듈 (Order Management)

> 본 모듈은 **Client의 상품 구매부터 Admin의 출고 처리 및 배송 완료까지의 주문 생명주기**를 관리합니다.
>
> 결제는 **Payment 모듈**, 상품은 **Product 모듈**, 재고는 **Inventory 모듈**에서 관리하며, Order는 각 모듈과 연동하여 주문 상태를 관리합니다.
>
> 본 모듈에서는 **환불, 교환, 반품 등의 클레임 기능을 제공하지 않습니다.**

---

## 1. 개요 (Overview)

Client가 상품을 구매하면 결제 완료 후 주문을 생성하고,
Admin은 주문 대기 목록을 확인하여 출고를 처리합니다.

배송이 완료된 후 Client가 배송 완료를 확정하거나,
배송 시작 후 일정 기간이 지나면 시스템이 자동으로 주문을 완료 처리합니다.

### Order Flow

```text
Product 조회
    ↓
Payment 완료
    ↓
Order 생성
    ↓
PENDING
(출고 대기)
    ↓
Admin 출고 처리
    ↓
SHIPPING
(배송 중)
    ↓
Client 배송 확정
    ↓
COMPLETED

재고 부족
    ↓
CANCELLED
```

---

## 2. 관리 데이터 (Data Scope)

### 2.1 Order

* Order ID
* Client ID
* 주문 상태
* 총 주문 금액
* 주문 일시
* 출고 일시
* 배송 완료 일시

### 2.2 Order Item

* Order Item ID
* Order ID
* Product ID
* Item ID
* SKU ID
* 상품명
* 주문 당시 가격
* 주문 수량
* 주문 당시 옵션 정보

> 주문 시점의 상품 정보와 가격을 보존하여 이후 Product 정보가 변경되더라도 기존 주문 데이터가 변하지 않도록 합니다.

---

## 3. 주문 상태 (Order Status)

```ts
PENDING
SHIPPING
COMPLETED
CANCELLED
```

### PENDING

* 결제가 완료되고 주문이 생성된 상태
* Admin의 출고 처리를 기다리는 상태

### SHIPPING

* Admin이 출고 처리를 완료한 상태
* Client에게 배송 중인 상태

### COMPLETED

* Client가 배송 완료를 확정한 상태
* 배송 시작 후 설정된 기간이 지나면 자동으로 완료 처리할 수 있습니다.

### CANCELLED

* 재고 부족 등의 사유로 주문 처리가 불가능한 상태
* 주문 취소 시 Inventory와 연동하여 재고를 복구할 수 있습니다.

---

## 4. 기능 요구사항 (Functional Requirements)

### 4.1 주문 생성

* Payment 모듈의 결제 완료를 확인한 후 주문을 생성합니다.
* 주문 생성 시 Order ID를 발급합니다.
* 주문 상품별 Order Item을 생성합니다.
* 주문 상태를 `PENDING`으로 설정합니다.
* 주문 생성 시점의 상품명, 가격, 옵션 정보를 Order Item에 저장합니다.
* 주문 생성과 관련된 데이터는 하나의 작업 단위로 처리합니다.

### 4.2 Client 주문 조회

* 로그인한 Client는 자신의 주문 목록을 조회할 수 있어야 합니다.
* 주문 상세 정보를 조회할 수 있어야 합니다.
* 주문 상태 및 배송 상태를 확인할 수 있어야 합니다.
* 다른 Client의 주문은 조회할 수 없어야 합니다.

### 4.3 Admin 주문 관리

* Admin은 주문 목록을 조회할 수 있어야 합니다.
* `PENDING` 주문을 출고 대기 Queue에서 확인할 수 있어야 합니다.
* 주문 상세 정보 및 주문 상품을 조회할 수 있어야 합니다.
* 주문을 출고 처리하여 `SHIPPING` 상태로 변경할 수 있어야 합니다.
* 재고 부족 등 주문 처리가 불가능한 경우 `CANCELLED` 상태로 변경할 수 있어야 합니다.

### 4.4 배송 완료

* Client는 배송 중인 주문의 배송 완료를 확정할 수 있어야 합니다.
* 배송 완료 확정 시 주문 상태를 `COMPLETED`로 변경합니다.
* 배송 시작 후 설정된 기간이 지나면 시스템이 자동으로 `COMPLETED` 처리할 수 있어야 합니다.

### 4.5 Inventory 연동

* 주문 처리에 필요한 SKU 재고를 Inventory 모듈과 연동합니다.
* 주문 처리 과정에서 재고 부족이 확인되면 주문을 `CANCELLED` 처리할 수 있어야 합니다.
* 주문 취소에 따라 필요한 재고 복구는 Inventory 모듈을 통해 처리합니다.

### 4.6 Payment 연동

* 주문 생성 전 또는 생성 과정에서 결제 완료 여부를 확인합니다.
* 결제가 완료되지 않은 주문은 정상 주문으로 생성되지 않아야 합니다.
* 동일한 결제에 대해 중복 주문이 생성되지 않아야 합니다.

## 5. 권한 (Permissions)

### Client

* 자신의 주문 생성 결과 조회
* 자신의 주문 목록 및 상세 조회
* 자신의 배송 상태 조회
* 배송 완료 확정

### Admin

* 전체 주문 조회
* 주문 상세 조회
* 출고 처리
* 주문 취소 처리

---

## 6. 비기능 요구사항 (Non-Functional Requirements)

### 6.1 접근 제어

* Client는 자신의 주문 데이터만 조회할 수 있어야 합니다.
* Admin은 권한에 따라 주문 관리 기능을 사용할 수 있어야 합니다.
* Client는 주문 상태를 임의로 변경할 수 없습니다.

### 6.2 데이터 일관성

* 주문 생성 시 Order와 Order Item 데이터가 일관되게 생성되어야 합니다.
* 주문 상태 변경은 허용된 상태 흐름을 따라야 합니다.

```text
PENDING → SHIPPING → COMPLETED
PENDING → CANCELLED
```

* `COMPLETED` 또는 `CANCELLED` 상태의 주문은 임의로 이전 상태로 되돌릴 수 없습니다.

### 6.3 중복 처리 방지

* 동일한 Payment에 대해 중복 Order가 생성되지 않아야 합니다.
* 출고 처리 및 배송 완료 처리가 중복 실행되지 않아야 합니다.

### 6.4 자동 처리

* 배송 시작 일시를 기준으로 설정된 기간이 지나면 배송 완료를 자동 처리할 수 있어야 합니다.
