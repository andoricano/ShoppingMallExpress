# [PRD] 장바구니, 프로모션, 리워드 및 주문/이력 관리 모듈 (Order)

## 1. 개요 (Overview)
본 문서는 소비자가 상품 탐색 및 장바구니 이용 후, 쿠폰/적립금 등의 프로모션을 적용하여 최종 결제 금액 및 적립 예정금액을 서버 사이드에서 안전하게 산출하고, 주문 생성, 결제 상태 변경, 구매 확정에 따른 리워드 지급 연동 및 주문/결제 이력(History)을 조회하기까지의 구매 전반부 및 주문 관리 요구사항을 다룹니다.

---

## 2. 관리 데이터 범위 (Data Scope)

### 2.1 장바구니 및 위시리스트 데이터
- **위시리스트**: User ID, Product ID, 등록 일시
- **장바구니**: Cart ID, User ID, Product ID, Option SKU ID, 수량, 선택 여부(Checked)

### 2.2 프로모션 및 적립금 데이터 (Promotion & Points)
- **쿠폰 선점 및 적용 정보**: User Coupon ID, Coupon ID, 할인 유형(정률/정액), 최대 할인금액, 최소 주문금액 조건
- **적립금 사용 정보**: User ID, 보유 적립금 잔액, 사용 요청 적립금

### 2.3 주문서, 임시/확정 주문, 리워드 및 이력 데이터 (Orders & History)
- **주문서 입력 정보**: 수령인 이름, 연락처, 배송지 주소, 픽업 여부/장소, 배송 요청사항
- **주문 데이터**: 
  - Order ID, User ID, 주문 상태 (`결제대기`, `주문접수`, `배송중`, `배송완료`, `구매확정`, `취소` 등)
  - 원 상품 금액, 배송비, 쿠폰 할인금액, 적립금 사용금액, **최종 결제 금액 (`total_amount` / Source of Truth)**
  - **적립 예정금액 스냅샷 (`expected_reward_amount`)**: 주문 생성 시점의 상품/회원 등급별 적립률 기준으로 고정된 적립 예정금액
  - 임시 재고/프로모션 점유 만료 일시 (TTL)
- **주문/결제 이력 (Order History)**: 
  - 주문별 상품 리스트(옵션, 수량, 단가), 배송지 정보, 사용된 프로모션/적립 내역
  - Payment 모듈 매핑 정보 (`payment_id`, `tid`, 결제 수단, 영수증 URL 등)

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 관심상품(위시리스트) 및 장바구니 관리 (Client)
- **위시리스트**: 마음에 드는 상품 토글 추가/삭제 및 마이페이지 내 모아보기
- **장바구니 관리**: 상품 옵션/수량 선택, 장바구니 내 수량 변경, 개별/선택/일괄 삭제

### 3.2 주문서 작성 및 프로모션 입력 (Client & Server)
- **진입 경로**: 장바구니 선택 구매 또는 상품 상세 '바로 구매'
- **정보 입력**: 배송지 선택/입력, 픽업 매장 지정, 수령인 정보 작성
- **프로모션 선택 및 적립 예정 안내**: 
  - 보유 쿠폰 조회 및 적용 선택 (Coupon ID)
  - 보유 적립금 내에서 사용 희망 적립금 금액 입력
  - **실시간 안내 표기**: 예상 할인 금액, 최종 결제 예정 금액, 구매 확정 시 적립 예정 금액 실시간 산출 표시 (단순 UI 참고용)

### 3.3 주문 생성, 서버 사이드 금액/리워드 검증 및 자원 임시 점유 (System Engine - Core Sequence)
> **보안 원칙**: 클라이언트가 전달한 금액/할인/적립 관련 모든 정보는 무시하며, 백엔드 단일 트랜잭션(Sequence) 내에서 모든 금액과 적립 예정액을 재계산 및 검증합니다.

1. **상품가 & 재고 검증**: DB 내 실제 상품/SKU 원가 조회 및 구매 수량 재고 점유(Hold)
2. **프로모션 유효성 검증**:
   - **쿠폰**: 해당 유저의 보유 여부, 만료일, 최소 주문금액 조건 충족 여부 DB 검증 후 쿠폰 할인액 계산
   - **적립금**: 유저의 실제 보유 적립금 잔액 DB 조회 후, 요청 금액이 잔액 이하인지 검증
3. **최종 결제 금액 및 적립 예정액 확정 (Source of Truth)**:
   - `최종 금액 = (실제 상품 원가 합) + (배송비) - (검증된 쿠폰 할인액) - (검증된 사용 적립금)`
   - `적립 예정금액(expected_reward_amount) = (상품별/등급별 적립 대상 금액) * (적립률)` 스냅샷 확정
4. **Order 생성 및 자원 선점 (Hold)**:
   - `Orders` 테이블에 `결제대기` 상태로 주문 생성 (`total_amount`, `expected_reward_amount` 저장)
   - 재고, 선택한 쿠폰(사용 임시 블록), 사용 요청 적립금(임시 차감)에 대해 일정 시간(예: 10분) TTL 적용하여 임시 선점 처리

### 3.4 결제 및 주문 라이프사이클 처리 (System Engine)
- **결제 성공 시 (이벤트 수신)**:
  - Payment 모듈로부터 `결제 완료` 비동기 이벤트 수신
  - 주문 상태 변경: `[결제대기] -> [주문접수]`
  - 임시 점유 자원 확정: 재고 차감 확정, 쿠폰 `사용완료` 처리, 적립금 `실제 소진` 처리
- **구매 확정 및 리워드 지급 이벤트 연동 (Purchase Confirmation)**:
  - 배송 완료 후 사용자가 '구매 확정' 클릭 시 또는 자동 구매 확정 기한 도달 시 상태를 `[구매확정]`으로 변경
  - **리워드 모듈 연동**: Reward 모듈로 `GRANT_REWARD(User ID, Order ID, expected_reward_amount)` 비동기 이벤트를 발행하여 실제 적립금 지급 처리
- **결제 실패 / 이탈 / TTL 만료 시**:
  - 선점했던 재고, 쿠폰 사용권, 적립금을 즉시 원복(Rollback) 및 복구
- **취소 및 반품 (Cancel & Refund)**:
  - 구매 확정 전 취소 시: 재고 원복, 사용한 쿠폰/적립금 복구
  - 구매 확정 후 반품/환불 시: Reward 모듈로 `REVOKE_REWARD(User ID, Order ID)` 이벤트를 발행하여 지급되었던 적립금 회수 처리 연동

### 3.5 주문 및 결제 이력 조회 (Order History)
- **주문 목록 조회 (Client - 마이페이지)**:
  - 유저별 과거 주문 내역 리스트 조회 (주문일시, 대표 상품명, 최종 결제금액, 주문 상태, 적립 예정/완료 금액)
- **주문 상세 조회 (Client & Admin)**:
  - `Order ID` 기준 단일 주문 상세 정보 제공
  - Order 정보 + Payment 결제 상세 정보(결제수단, `tid`, 영수증 URL 등) + 프로모션/적립 이력을 결합하여 응답

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **금액 보안 및 스냅샷 보장 (Security & Snapshot Integrity)**:
  - 모든 금액 계산 및 할인/적립률 검증은 100% 서버 사이드에서 수행.
  - 적립 예정금액은 주문 생성 시점의 스냅샷 데이터를 기준으로 고정되어 향후 적립률 정책이 바뀌어도 기존 주문에 영향을 주지 않음.
- **트랜잭션 일관성 (Atomicity)**:
  - 주문 생성 시 재고 점유, 쿠폰 검증, 적립금 임시 차감은 단일 트랜잭션으로 처리되어 하나라도 실패 시 전체 롤백.
- **이벤트 기반 리워드 연동 (Event-driven Reward Decoupling)**:
  - Reward 모듈과의 결합도를 낮추기 위해 구매 확정/취소 시 비동기 이벤트를 통한 상태 전달 처리.
