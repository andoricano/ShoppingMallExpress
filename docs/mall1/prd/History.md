# [PRD] 주문 및 감사 로그 이력 관리 모듈 (Order History & Audit Logs)

## 1. 개요 (Overview)
본 문서는 쇼핑몰 SaaS의 주문 이력 및 거래/재고/결제 감사 로그(Audit Log) 관리를 위한 PRD입니다. 
결제 완료된 주문 데이터를 스냅샷 형태로 안전하게 보존하고, 주문 상태 전환·재고 변동·결제 및 환불 내역을 타임스탬프 기반의 불변 로그(Immutable Log)로 기록하여 소비자 CS 대응, 어드민 조회, 정산 검증을 지원하는 것을 목표로 합니다.

---

## 2. 관리 데이터 범위 (Data Scope)

### 2.1 주문 이력 데이터 (Order History Snapshot)
- **주문 고유 식별자**: Order ID, User ID, 주문 일시
- **주문 시점 스냅샷 (Snapshot)**: 주문 당시의 상품명, 옵션명(SKU), 구매 단가, 수량, 할인 적용액, 최종 결제 금액
- **배송 및 수령 정보**: 수령인명, 연락처, 배송지 주소, 픽업 매장 정보, 배송 요청사항
- **결제 요약**: 결제 수단, PG 승인 식별자 (TID)

### 2.2 감사 로그 데이터 (Audit Log Data)
- **주문 상태 변경 로그**: Order ID, 변경 전/후 상태, 처리자 유형 (`소비자`/`어드민`/`시스템`), 처리자 ID, 변경 사유, 처리 일시 (Timestamp)
- **재고 변동 이력 로그**: Inventory Log ID, SKU ID, 변동 전/후 수량, 변동 수량 (+/-), 변동 사유 (`주문차감`/`취소복구`/`수동입출고`/`손실` 등), 담당자 ID, 발생 일시
- **결제/환불 이력 로그**: Payment Log ID, Order ID, PG 거래번호 (TID), 트랜잭션 유형 (`승인`/`취소`/`부분환불`/`실패`), 결제 금액, 실패/환불 사유 코드, 처리 일시

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 소비자 주문 이력 자동 생성 (System Engine)
- **이력 스냅샷 생성**: 결제 완료 이벤트 발생 시, 해당 시점의 상품 정보, 가격, 할인 정책, 배송지, 결제 수단을 '수정 불가능한 스냅샷' 데이터 형태로 자동 생성 및 저장
- **원천 데이터 분리**: 향후 상품명이나 가격이 변경되더라도 과거 주문 이력 데이터는 변동되지 않도록 독립 보존

### 3.2 주문 이력 조회 (Client & Admin)
- **소비자 조회 (Client App/Web)**:
  - 마이페이지에서 본인의 과거 및 현재 주문 목록, 상세 주문 내역, 타임라인 형태의 주문 상태 변화 조회
- **관리자 조회 (Admin Web/App)**:
  - 전체 소비자의 주문 이력 통합 조회
  - 다중 검색 필터 제공: 기간 설정 (일/주/월/자율), 주문 상태별, 소비자 계정별, 주문 번호별, 상품별 검색

### 3.3 주문 상태 변경 이력 관리 (System & Admin)
- **실시간 추적 이력 기록**: 주문 접수부터 결제 완료, 상품 준비, 배송/수령, 완료, 취소/환불 등 제6조의 상태값 전환 시 매 순간 로그 생성
- **로그 필수 기록 항목**: 상태 변경 시각, 처리자 (소비자, 특정 어드민 계정 ID, 자동 처리 시스템), 변경 사유 (예: "고객 요청에 의한 배송 전 취소")
- **추적 UI 노출**: 사업자 어드민 및 소비자 마이페이지 내 상세 타임라인 UI로 변경 이력 제공

### 3.4 재고 변동 이력(Audit Trail) 관리 (Admin Only)
- **자동/수동 변동 전체 기록**:
  - `주문 모듈` 발생에 따른 자동 차감 (-)
  - 사업자 백오피스에서의 수동 입출고 조정 (+/-)
  - `주문/취소 모듈`에 따른 주문 취소 및 반품 확정 시 재고 원상 복구 (+)
- **이력 세부 정보**: 변동 SKU, 변동 수량, 변동 전/후 잔여 재고, 사유 구분, 처리 시각, 담당 어드민 계정 저장을 통한 어드민 웹 내 조회 기능 제공

### 3.5 결제 및 환불 이력 관리 (Admin & System)
- **타임스탬프 결제 이력**: PG사를 통해 처리된 결제 승인, 전액 취소, 부분 환불, 결제 실패건 발생 시 시각 기반 트랜잭션 로그 기록
- **정산 데이터 활용**: PG 승인 번호(TID), 환불 수수료 차감 내역 등을 기록하여 어드민 정산/재무 대시보드 및 가맹점 정산 증빙용으로 조회 제공

---

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **데이터 불변성 (Immutability & Append-Only)**:
  - 일단 기록된 상태 변경 로그, 재고 변동 이력, 결제/환불 이력은 어드민을 포함한 그 누구도 수정하거나 삭제할 수 없도록 Append-Only 방식으로만 DB에 추가 저장
- **감사 추적성 (Auditability)**:
  - 전자상거래 등에서의 소비자보호에 관한 법률 등 법적 의무 보존 기간(주문/결제 이력 5년 등)을 준수하는 데이터 백업 및 보존 정책 적용
