# [PRD] 재고 관리 모듈 (Inventory Management) - Admin Only

> **[시스템 접근 범위 및 모듈 경계 명시]**  
> 본 모듈은 **100% 어드민(Admin Web & App / 백오피스) 전용 관리자 모듈**입니다.  
> 일반 구매자(Customer)용 UI는 일체 존재하지 않으며, 구매자 단에서의 재고 확인 및 차감은 `상품 모듈` 및 `주문 모듈`과의 이벤트/API 연동을 통해서만 백그라운드로 처리됩니다.

---

## 1. 개요 (Overview)
본 문서는 쇼핑몰 SaaS의 **어드민 전용 재고 관리 모듈**에 대한 PRD입니다. 
사업자 및 매장 관리자가 백오피스에서 각 SKU(Stock Keeping Unit: 재고 관리 최소 단위)별 수량을 정확히 제어·추적하고, 어드민 수동 입출고, 안전재고 알림, 어드민 작업 감사 로그(Audit Log)를 안전하게 관리하는 것을 목표로 합니다.

---

## 2. 권한 및 관리 데이터 범위 (Permissions & Data Scope)

### 2.1 어드민 접근 권한 (Admin RBAC:role-based access control) (IT) 역할 기반 접근통제 ((권한이 있는 사용자들만 접근할 수 있는 보안 방법))
- **플랫폼 최고 관리자 (Super Admin)**: 전체 매장/SKU 재고 조회, 강제 수량 조정, 이력 조회, 안전재고 설정
- **매장 운영자 (Store Operator)**: 담당 매장/상품의 SKU 재고 조회, 입출고 수동 조정, 안전재고 알림 수신
- **일반 구매자 (Customer)**: 본 모듈 직접 접근 절대 불가 (상품/주문 API를 통한 백그라운드 참조만 가능)

### 2.2 SKU/재고 식별 데이터
- **SKU ID (Stock Keeping Unit)**: 옵션/품목 단위 고유 식별자
- **상품 매핑 ID**: 상품 관리 모듈의 Product ID 연동

### 2.3 재고 수량 및 상태 데이터
- **현재 실재고 (Current Stock)**: 실제 보유 수량
- **안전재고 (Safety Stock)**: 품절 임박 알림 기준 수량
- **재고 상태**: 판매중 (In Stock), 품절 임박 (Low Stock), 품절 (Sold Out), 비활성화 (Disabled)

---

## 3. 기능 요구사항 (Functional Requirements - Admin Dedicated)

### 3.1 SKU 매핑 및 초기 재고 설정 (Admin Only)
- **기능 설명**: 어드민 관리자 웹에서 상품 등록/수정 시 생성된 옵션(SKU)별로 초기 재고 수량 및 안전재고 수량을 설정합니다.
- **주요 입력 항목**: SKU 코드, 초기 재고 수량, 안전재고 기준 수량

### 3.2 재고 목록 및 대시보드 조회 (Admin Web/App Only)
- **어드민 전용 UI**:
  - 관리자 웹 및 앱에서 SKU별 실재고, 안전재고 상태, 품절 여부를 실시간 검색/조회
  - 검색 필터: 상품명, SKU 코드, 재고 상태(정상/임박/품절), 카테고리
  - 시각적 배지: 안전재고 이하 달성 시 '품절 임박' 경고 배지 표기 및 어드민 메인 대시보드 위젯 노출

### 3.3 어드민 재고 수동 조정 및 사유 등록 (Admin Only)
- **수동 입출고 제어**: 어드민 권한자가 재고 조사, 입고, 파손/손실 등의 사유로 수량을 (+ / -) 수동 조정
- **어드민 필수 입력 항목**: [신규 입고], [재고 조사], [파손/손실], [기타] 중 선택 및 어드민 전용 사유 메모 작성

### 3.4 백그라운드 자동 재고 연동 (주문/취소 모듈 이벤트 연동)
- **자동 차감**: `주문 모듈`에서 결제 완료 이벤트 발생 시 해당 SKU 재고 백그라운드 자동 차감 (-)
- **자동 복구**: `주문/취소 모듈`에서 주문 취소, 반품 확정 이벤트 발생 시 해당 SKU 재고 백그라운드 자동 복구 (+)

### 3.5 품절 자동 트리거 & 외부 모듈 이벤트 발행
- **품절 자동 전환**: 실재고 수량이 0이 되면 어드민 상태를 `Sold Out`으로 즉시 변경하고 `상품 모듈`에 품절 이벤트 발행
- **판매 재개 연동**: 어드민 수동 입고 또는 주문 취소로 수량이 1 이상 복구되면 `In Stock` 상태로 복구 및 `상품 모듈`에 판매 재개 이벤트 발행

### 3.6 어드민 감사 로그 (Audit Log) & PUSH 알림
- **불변 로그 (Immutable Audit Trail)**:
  - 변동 일시, SKU ID, 변동 전/후 수량, 변동 유형(주문차감/취소복구/수동조정 등), **담당 어드민 계정 ID** 기록
- **어드민 전용 알림**:
  - 실재고가 '안전재고 수량' 이하로 하강 시 어드민 웹 상단 알림 및 어드민 전용 앱 PUSH 발송

### 3.7 어드민 비활성화 및 논리적 삭제 (Disable)

- **비활성화 (Disabled)**:
  - 주문 이력이 존재하는 SKU 삭제 요청 시 DB 물리 삭제(Physical Delete)를 금지하고 `Disabled(비활성화)` 상태 처리
  - 비활성화된 SKU는 구매자 프론트엔드 노출이 즉시 차단되며, 어드민 목록 필터링으로만 조회 가능

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **어드민 접근 보안 및 API 격리**:
  - 구매자용 Public API와 어드민 전용 Private API 엔드포인트를 완전히 격리하고, 어드민 권한(JWT Role/RLS) 검증 강화
- **데이터 일관성 (Concurrency Control)**:
  - 어드민 수동 조정과 고객 주문 차감이 동시 발생할 때 재고가 음수(-)가 되지 않도록 DB 트랜잭션 보장
- **감사 추적성 (Auditability)**:
  - 어드민의 모든 재고 변동 내역은 수정/삭제가 불가능한 Append-Only 로그 형태로 보관
