# [PRD-PROD-03] 계층형 카테고리 트리 관리 (Category Tree Management)

## 1. 화면 개요 (Screen Overview)

- **화면 경로**: `/admin/products/categories`

- **화면 목적**: 쇼핑몰의 계층형 카테고리(대/중/소) 트리 구조를 관리하고, 카테고리의 생성·수정·삭제·순서 변경(Drag & Drop) 및 전시 노출 여부를 설정하는 인터페이스 제공.

- **주요 사용자**: 어드민 관리자, 상품 운영 담당자

---

## 2. 기능 요구사항 (Functional Requirements)

### 2.1 카테고리 트리 뷰 (Tree View Interaction)

- **계층 구조 지원**: 최대 3단계(Depth 1: 대분류, Depth 2: 중분류, Depth 3: 소분류) 계층 노드 표시.

- **트리 펼침/접힘 (Expand/Collapse)**:
  - 각 노드 좌측 아이콘으로 하위 카테고리 접기/펼치기 가능.
  - [전체 펼치기] / [전체 접기] 상단 토글 버튼 제공.

- **드래그 앤 드롭 (Drag & Drop) 순서 및 계층 변경**:
  - 마우스 드래그를 통한 동일 계층 내 노출 순서(`sort_order`) 변경.
  - 상위 노드로 드래그하여 소속 계층 이동 가능.
  - 단, 최대 Depth 3 제한을 준수해야 함.
  - 변경 발생 시 [순서 저장] 버튼 활성화.
  - [순서 저장] 클릭 시 변경된 트리 구조를 일괄 API로 저장.

- **노드 선택 (Node Selection)**:
  - 특정 카테고리 노드 클릭 시 우측 '카테고리 상세 설정' 영역에 해당 카테고리 데이터 바인딩.

---

### 2.2 카테고리 상세 설정 및 생성/수정 (Category Form)

- **기본 정보**:
  - **카테고리 ID (`category_id`)**: UUID (Read-Only).
  - **카테고리명 (`category_name`)**: 텍스트 입력 (필수, 최대 50자).
  - **상위 카테고리 (`parent_category_id`)**: 드롭다운 선택.
    - 최상위 카테고리인 경우 `없음` 선택.

- **노출 상태 (`status`)**:
  - `DISPLAY` (진열중) / `HIDDEN` (숨김) 선택.
  - `HIDDEN`은 해당 카테고리를 쇼핑몰 전시 영역에서 비활성화하는 상태로 정의.
  - 상위 카테고리가 `HIDDEN`이더라도 하위 카테고리의 상태 자체를 변경하지 않음.
  - 단, Client 전시 API에서는 상위 카테고리 중 하나라도 `HIDDEN`인 경우 해당 하위 카테고리 및 연결 상품을 노출 대상에서 제외함.
  - 하위 카테고리의 개별 상태가 `HIDDEN`인 경우에도 해당 카테고리와 연결된 상품은 Client 전시 API에서 제외함.

- **노출 순서 (`sort_order`)**:
  - 동일 상위 카테고리 내에서의 정렬 순서를 나타내는 숫자 값.

- **연관 데이터 표시 (Read-Only Info)**:
  - **매핑된 상품 수**: 해당 카테고리에 지정된 상품 개수 노출.
  - [해당 상품 목록 보기] 링크 제공.
  - 클릭 시 `/admin/products?categoryId=xxx`로 이동.

---

### 2.3 카테고리 생성 / 삭제 (Node Operations)

#### A. 카테고리 신규 추가

1. **[+ 최상위 카테고리 추가]** 또는 선택 노드 우측 **[+ 하위 추가]** 버튼 클릭.
2. 우측 입력 폼이 신규 카테고리 작성 모드로 전환.
3. 데이터 입력 후 [생성] 클릭.
4. 유효성 검사 통과 후 카테고리 생성 API 호출.
5. 생성 성공 시 트리에 신규 카테고리를 반영.

#### B. 카테고리 삭제 (Safety Check Rules)

1. 카테고리 노드 우측 **[삭제]** 버튼 클릭 시 삭제 가능 여부 사전 검증.
   - **하위 카테고리가 존재하는 경우**: 삭제 불가.
     - `"하위 카테고리가 존재합니다. 하위 항목을 먼저 삭제하거나 이동해주세요."`
   - **매핑된 상품이 존재하는 경우**: 삭제 불가.
     - `"해당 카테고리에 매핑된 상품이 N개 존재합니다. 상품 카테고리를 먼저 변경해주세요."`

2. 삭제 가능한 경우 Confirm Alert Modal 호출.
3. 사용자가 삭제를 확인하면 카테고리 삭제 API 호출.
4. 삭제 방식은 Soft Delete 또는 물리 삭제 중 백엔드 정책에 따름.
5. 삭제 성공 시 트리를 다시 조회하여 최신 상태 반영.

## 3. 유효성 검사 및 제한 규칙 (Validation & Constraints)

| 구분 | 규칙 및 조건 | 비고 / 에러 메시지 |
| :--- | :--- | :--- |
| **최대 Depth 제한** | 최대 3단계(Depth 3)까지만 생성 및 이동 가능 | Depth 3 하위로 이동 불가능 |
| **카테고리명** | 필수 입력, 1~50자 | `"카테고리명을 입력해주세요. (최대 50자)"` |
| **중복 명칭 검증** | 동일한 상위 노드 내 중복 카테고리명 불허 | `"동일 계층 내에 이미 존재하는 카테고리명입니다."` |
| **삭제 제한** | 하위 노드 존재 또는 매핑 상품 수 > 0 시 삭제 차단 | `"연관된 상품 또는 하위 카테고리가 있어 삭제할 수 없습니다."` |

## 4. API 연동 매핑 (API Interface Mapping)

| UI 이벤트 / 액션 | HTTP Method & Endpoint | Request Payload / Params | 비고 |
|---|---|---|---|
| **전체 카테고리 트리 로딩** | `GET /api/admin/categories/tree` | - | 전체 계층형 카테고리 조회 |
| **카테고리 신규 생성** | `POST /api/admin/categories` | `CreateCategoryPayload` | 신규 카테고리 생성 |
| **카테고리 정보 수정** | `PUT /api/admin/categories/:id` | `params: { id }`, `UpdateCategoryPayload` | 카테고리명, 상위 카테고리, 상태, 정렬 순서 수정 |
| **트리 구조/순서 일괄 변경** | `PATCH /api/admin/categories/reorder` | `ReorderCategoryPayload` | Drag & Drop 후 저장 |
| **카테고리 삭제** | `DELETE /api/admin/categories/:id` | `params: { id }` | 하위 카테고리 및 매핑 상품 검증 후 삭제 |

> 카테고리 삭제는 하위 카테고리 또는 매핑된 상품이 존재하는 경우 처리하지 않는다.

## 5. 예외 처리 및 UI 피드백 (Exception Handling)

1. **Drag & Drop 순서 변경 후 미저장 이탈 시**:
   - 트리 순서를 변경했으나 [순서 저장]을 누르지 않고 타 메뉴 이동 시 Dirty Check 경고 모달 출력.
   - `"변경된 카테고리 순서가 저장되지 않았습니다. 정말 나가시겠습니까?"`

2. **카테고리 삭제 차단 인터랙션**:
   - 삭제 버튼에 마우스 호버 시 하위 카테고리 존재 여부 및 매핑 상품 수를 확인.
   - 삭제 불가능한 경우 버튼을 `disabled` 처리하고 툴팁으로 사유 표시.

3. **상위 카테고리 숨김 설정 시 알림**:
   - 상위 카테고리를 `HIDDEN`으로 변경하려 할 때 안내 모달 출력.
   - `"상위 카테고리를 숨김 처리하면 모든 하위 카테고리 및 해당 상품들이 사용자 화면에 노출되지 않습니다. 진행하시겠습니까?"`

4. **카테고리 이동 시 Depth 초과 방지**:
   - Drag & Drop 대상 카테고리의 하위 트리 깊이를 계산하여 Depth 3을 초과하는 경우 Drop Zone 비활성화.
   - 잘못된 이동 요청이 서버로 전달되지 않도록 Client에서 1차 검증.
   - 서버에서도 동일한 Depth 제한을 최종 검증.

5. **동시 수정 충돌**:
   - 다른 관리자가 동일 카테고리를 수정한 경우 `409 Conflict`를 반환.
   - `"다른 관리자에 의해 최신 정보가 변경되었습니다. 페이지를 새로고침합니다."` 메시지를 출력한 후 최신 트리를 재조회.
