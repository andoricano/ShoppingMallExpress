# [PRD-PROD-01] 어드민 상품 목록 및 일괄 관리 (Product List & Batch Actions)

## 1. 화면 개요 (Screen Overview)

- **화면 경로**: `/admin/products`

- **화면 목적**:
  등록된 상품의 목록 조회, 검색 및 필터링, 상품 진열 상태 변경, 카테고리 매핑 변경 및 상품 Soft Delete 처리를 수행하는 통합 관리 화면.

- **주요 사용자**:
  어드민 관리자, 상품 운영 담당자

- **재고 관리 원칙**:
  상품 관리 화면에서는 원천 재고(SKU)의 수량을 직접 수정하지 않는다.
  실제 판매에 따른 재고 차감 및 복구는 주문(Order) 모듈에서 처리한다.

---

## 2. 기능 요구사항 (Functional Requirements)

### 2.1 검색 및 필터링 (Search & Filters)

1. **카테고리 필터**:

   - 계층형 드롭다운 선택
     - 대분류 → 중분류 → 소분류 순으로 선택 가능.
   - 선택된 카테고리에 매핑된 상품을 조회한다.
   - 최종 선택된 `categoryId`를 조회 파라미터로 전송한다.
   - 상품이 여러 카테고리에 매핑되어 있는 경우, 해당 카테고리 중 하나라도 일치하면 조회 대상에 포함한다.

2. **진열 상태 필터**:

   - 옵션:
     - `전체`
     - `DISPLAY` (진열중)
     - `HIDDEN` (숨김)
     - `SOLD_OUT` (품절)
   - 기본 조회 시 `DELETED` 상태의 상품은 제외한다.
   - `SOLD_OUT`은 원천 재고 상태에 따라 자동 전환될 수 있으며, 어드민에서 수동으로 변경할 수도 있다.
   - `HIDDEN`은 상품의 전시 여부를 의미하며 재고 상태와 독립적으로 관리한다.

3. **검색어 입력 (Search Query)**:

   - 검색 대상:
     - 상품명 (`product_name`)
     - 상품 ID (`product_id`)
   - UUID 형식의 입력값은 `product_id` 정확 일치 검색을 지원한다.
   - 일반 문자열은 `product_name` 부분 검색을 수행한다.
   - 상품 ID를 검색할 때에는 UUID 전체 입력 또는 시스템에서 지원하는 축약 ID 검색 정책을 따른다.

4. **초기화 버튼**:

   - 모든 검색 필터 및 입력값을 기본값으로 초기화한다.
   - 초기화 후 1페이지부터 다시 조회한다.

### 2.2 데이터 테이블 (Data Table)

| 컬럼명 | 표시 데이터 | UI/UX 상세 동작 |
|---|---|---|
| **선택 (Checkbox)** | 체크박스 | 전체 선택 / 개별 선택 가능. 하나 이상의 상품 선택 시 **Batch Action Bar** 활성화 |
| **대표 이미지** | `main_image_url` | 50x50 썸네일 이미지. 이미지가 없을 경우 기본 Placeholder 노출 |
| **상품명 / ID** | `product_name`, `product_id` | 상품명 클릭 시 `/admin/products/:id/edit`로 이동. 상품 ID는 약식 표시 및 클립보드 복사 기능 제공 |
| **가격 정보** | `base_price`, `discounted_price` | 정상가와 할인가를 함께 표시. 할인 미적용 시 정상가만 표시 |
| **카테고리** | 카테고리 경로 | 예: `의류 > 상의 > 반팔티`. 다중 카테고리 매핑 상품은 대표 카테고리를 우선 표시하고 추가 카테고리 존재 여부를 표시할 수 있음 |
| **재고** | 원천 SKU 재고 정보 | 현재 원천 재고 상태를 조회용으로 표시. 상품 목록에서 재고 수량을 직접 수정하지 않음 |
| **진열 상태** | `status` | Badge UI 적용. `DISPLAY`: 진열중, `HIDDEN`: 숨김, `SOLD_OUT`: 품절 |
| **등록일시** | `created_at` | `YYYY-MM-DD HH:mm` 포맷 |
| **관리 (Actions)** | 버튼 그룹 | `[수정]`: 수정 페이지 이동. `[삭제]`: Soft Delete 확인 모달 호출 |

### 2.3 일괄 관리 기능 (Batch Actions)

테이블 내 체크박스로 1개 이상의 상품이 선택되었을 때 상단에 **Batch Action Bar**가 노출된다.

#### A. 진열 상태 일괄 변경

1. **[진열 상태 일괄 변경]** 버튼 클릭 시 모달을 호출한다.

2. Target Status를 선택한다.

   - `DISPLAY` (진열중)
   - `HIDDEN` (숨김)
   - `SOLD_OUT` (품절)

3. `SOLD_OUT`은 자동 상태 전환뿐만 아니라 어드민의 수동 변경도 허용한다.

4. **[확인]** 클릭 시 선택된 상품의 상태를 일괄 변경한다.

5. 처리 완료 후 다음과 같은 토스트를 출력한다.

   - `"N개 상품의 상태가 변경되었습니다."`

---

#### B. 카테고리 매핑 일괄 변경

1. **[카테고리 변경]** 버튼 클릭 시 카테고리 선택 모달을 호출한다.

2. 대상 카테고리를 대/중/소 계층으로 선택한다.

3. 선택한 상품에 대해 카테고리 매핑을 변경한다.

4. 상품은 여러 카테고리에 매핑될 수 있으므로 기존 카테고리 매핑을 유지하면서 새로운 카테고리를 추가하거나, 사용자의 명시적인 선택에 따라 기존 매핑을 교체할 수 있다.

5. 대표 카테고리가 변경되는 경우 대표 카테고리 지정 여부를 함께 처리한다.

6. 카테고리 매핑 변경은 하나의 트랜잭션으로 처리하며 전체 성공 또는 전체 실패를 보장한다.

7. 처리 완료 후 다음과 같은 토스트를 출력한다.

   - `"N개 상품의 카테고리가 변경되었습니다."`

---

### 2.4 상품 삭제 (Soft Delete)

#### A. 단일 삭제

1. 상품 목록의 `[삭제]` 버튼 클릭 시 Confirm Alert Modal을 호출한다.

2. 다음과 같은 확인 메시지를 출력한다.

   > "선택한 상품을 삭제하시겠습니까? 삭제 처리된 상품은 쇼핑몰 화면에서 즉시 노출되지 않습니다."

3. **[삭제 확인]** 클릭 시 해당 상품의 `status`를 `DELETED`로 변경한다.

4. 삭제 성공 시 목록을 다시 조회한다.

---

#### B. 일괄 삭제

1. 하나 이상의 상품을 선택한 상태에서 Batch Action Bar의 **[일괄 삭제]** 버튼을 제공한다.

2. Confirm Alert Modal을 호출하여 선택된 상품 수를 표시한다.

   > "선택한 N개 상품을 삭제하시겠습니까?"

3. **[삭제 확인]** 클릭 시 일괄 Soft Delete API를 호출한다.

4. 전체 작업은 하나의 트랜잭션으로 처리한다.

5. 성공 시 목록을 다시 조회하고 다음 토스트를 출력한다.

   - `"N개 상품이 삭제되었습니다."`

## 3. API 연동 매핑 (API Interface Mapping)

| UI 이벤트 / 액션 | HTTP Method & Endpoint | Request Payload / Params | 비고 |
|---|---|---|---|
| **목록 로딩 / 검색** | `GET /api/admin/products` | `page`, `limit`, `status`, `categoryId`, `searchQuery` | Query String |
| **상태 일괄 변경** | `PATCH /api/admin/products/batch/status` | `{ productIds: string[], status: 'DISPLAY' \| 'HIDDEN' \| 'SOLD_OUT' }` | Batch Action |
| **카테고리 일괄 변경** | `PATCH /api/admin/products/batch/category` | `{ productIds: string[], categoryIds: string[], mode: 'ADD' \| 'REPLACE' }` | 다중 카테고리 매핑 지원 |
| **단일 상품 삭제** | `DELETE /api/admin/products/:id` | `params: { id }` | Soft Delete |
| **상품 일괄 삭제** | `DELETE /api/admin/products/batch` | `{ productIds: string[] }` | Soft Delete |

> 재고 수량 변경 API는 상품 모듈에서 제공하지 않는다.

> 상품 판매에 따른 원천 재고 차감 및 복구는 Order 모듈에서 처리한다.

## 4. 상태 및 재고 처리 정책 (Status & Inventory Policy)

### 4.1 `HIDDEN` 상태

- `HIDDEN`은 상품의 **전시 여부**를 제어하는 상태이다.
- 원천 재고와 독립적으로 관리한다.
- 재고가 충분하더라도 관리자가 `HIDDEN`으로 설정하면 쇼핑몰 전시 API에서 제외한다.
- `HIDDEN` 상품의 원천 재고가 변경되더라도 자동으로 `DISPLAY`로 변경하지 않는다.

### 4.2 `SOLD_OUT` 상태

- `SOLD_OUT`은 상품의 **구매 가능 여부**를 나타내는 상태이다.
- 원천 재고가 0이 되면 시스템에서 자동으로 `SOLD_OUT`으로 전환할 수 있다.
- 어드민 관리자는 필요한 경우 `SOLD_OUT` 상태를 수동으로 설정할 수 있다.
- 수동으로 `SOLD_OUT`으로 설정된 상품은 재고가 다시 증가하더라도 자동으로 `DISPLAY`로 복구하지 않는다.
- 자동 전환과 수동 전환의 구분이 필요한 경우 별도의 상태 변경 사유 또는 관리 메타데이터를 기록할 수 있다.

### 4.3 재고 변경

- 상품(Product) 모듈에서는 SKU의 원천 재고 수량을 직접 변경하지 않는다.
- 주문(Order) 생성/취소/환불 등의 상태 변화에 따른 재고 차감 및 복구는 Order 모듈에서 처리한다.
- 상품 목록에서는 현재 재고를 조회하여 표시할 수 있으나 수정은 제공하지 않는다.

## 5. 예외 처리 및 UI 피드백 (Exception Handling)

1. **검색 결과 없음**:

   - 테이블 영역에 다음 안내문을 표시한다.

   > "조건에 맞는 상품이 존재하지 않습니다."

   - `[검색 초기화]` 버튼을 제공한다.

2. **유효하지 않은 상품 ID 입력**:

   - UUID 형식이 필요한 경우 클라이언트에서 사전 검증한다.
   - 잘못된 ID 형식은 서버 요청 전에 차단한다.

3. **일괄 작업 실패**:

   - 일괄 상태 변경 및 카테고리 변경은 전체 성공 또는 전체 실패를 기본 정책으로 한다.
   - 실패 시 변경 사항을 롤백하고 에러 토스트를 출력한다.

   > "일괄 작업 처리 중 오류가 발생했습니다. 변경 사항을 원복했습니다."

4. **상품 삭제 실패**:

   - 삭제 처리 실패 시 목록 데이터를 변경하지 않고 오류 토스트를 출력한다.

   > "상품 삭제에 실패했습니다. 잠시 후 다시 시도해주세요."

5. **네트워크 지연**:

   - 목록 로딩 시 테이블 전체에 **Skeleton Screen**을 적용한다.
   - 일괄 작업 및 삭제 처리 중 해당 버튼에 **Button Spinner**를 표시한다.
   - 처리 중 중복 요청을 방지하기 위해 액션 버튼을 비활성화한다.

6. **동시 수정 충돌**:

   - 다른 관리자가 상품 정보를 먼저 수정한 경우 서버의 충돌 응답을 기준으로 처리한다.
   - 최신 데이터를 다시 조회하도록 안내한다.

## 6. UI 상태 및 인터랙션 정책

### 6.1 상품 선택 상태

- 상품이 선택되지 않은 경우 Batch Action Bar를 비활성화한다.
- 하나 이상의 상품이 선택되면 Batch Action Bar를 활성화한다.
- 현재 페이지의 상품만 전체 선택할 수 있다.
- 페이지 이동 시 선택 상태 유지 여부는 프론트엔드 구현 정책에 따른다.
- 대량 작업 시 선택된 상품 수를 Batch Action Bar에 표시한다.

### 6.2 삭제 상품

- 기본 상품 목록에서는 `DELETED` 상품을 제외한다.
- 삭제된 상품의 수정 페이지 접근 시 수정 기능을 제한할 수 있다.
- 상품의 복구 기능은 별도의 상품 복구 정책이 정의된 경우에만 제공한다.

### 6.3 상태 변경과 재고의 관계

- `HIDDEN`과 `SOLD_OUT`은 서로 다른 의미를 가진다.
- `HIDDEN`은 전시 여부를 제어한다.
- `SOLD_OUT`은 구매 가능 여부를 제어한다.
- 재고가 부족하다는 이유만으로 상품을 `HIDDEN`으로 변경하지 않는다.
- 자동 `SOLD_OUT` 처리와 수동 상태 변경의 우선순위 및 복구 정책은 백엔드 상품 상태 정책과 동일하게 적용한다.
