# [PRD-PROD-02] 어드민 상품 등록 및 수정 (Product Form - Create & Edit)

## 1. 화면 개요 (Screen Overview)

- **화면 경로**:

  - 신규 등록: `/admin/products/new`
  - 정보 수정: `/admin/products/:id/edit`

- **화면 목적**:
  판매 상품의 기본 정보, 카테고리 매핑, 가격 및 할인 정책, 옵션 구성, 상세 내용 등을 등록·수정하는 인터페이스를 제공한다.

- **주요 사용자**:
  어드민 관리자, 상품 운영 담당자

- **재고 관리 원칙**:
  Product 모듈에서는 원천 SKU의 재고 수량을 직접 수정하지 않는다.
  상품에 SKU를 매핑하고 현재 원천 재고를 조회할 수 있으며, 실제 판매에 따른 재고 차감 및 복구는 Order 모듈에서 처리한다.

---

## 2. 입력 섹션별 기능 명세 (Section Specifications)

### 2.1 기본 정보 (Basic Information)

- **상품명 (`product_name`)**:
  텍스트 입력 (필수, 최대 100자).

- **진열 상태 (`status`)**:
  라디오 버튼 또는 세그먼트 컨트롤.

  - `DISPLAY` [진열중]
  - `HIDDEN` [숨김]
  - `SOLD_OUT` [품절]

  - 신규 등록 기본값: `DISPLAY`
  - `HIDDEN`은 상품의 전시 여부를 제어한다.
  - `SOLD_OUT`은 상품의 구매 가능 여부를 제어한다.
  - `SOLD_OUT`은 시스템에 의해 자동 전환될 수 있으며, 어드민에서 수동으로 설정할 수도 있다.
  - 수동으로 `SOLD_OUT`을 설정한 상품은 원천 재고가 증가하더라도 자동으로 `DISPLAY`로 복구하지 않는다.

- **진열 우선순위 (`sort_order`)**:
  숫자 입력 (선택, 기본값 `0`).

  - 숫자가 낮을수록 쇼핑몰 상단에 노출된다.
  - 동일한 우선순위에 대한 정렬 기준은 쇼핑몰 전시 API 정책을 따른다.

---

### 2.2 카테고리 매핑 (Category Mapping)

- **카테고리 선택 UI**:
  계층형 카테고리 선택 후 [추가] 버튼을 통해 Tag Chip 형태로 등록한다.

- **다중 카테고리 지정**:

  - 하나의 상품은 여러 카테고리에 매핑될 수 있다.
  - 최소 1개 이상의 카테고리 매핑을 필수로 한다.
  - 동일한 카테고리를 중복 매핑할 수 없다.

- **대표 카테고리 설정**:

  - 매핑된 카테고리 중 정확히 1개를 대표 카테고리로 지정할 수 있다.
  - 대표 카테고리는 상품의 Breadcrumb 및 대표적인 카테고리 경로 표시 기준으로 사용한다.
  - 대표 카테고리 역시 일반 카테고리 매핑 중 하나로 취급한다.

- **카테고리 상태 제한**:

  - `HIDDEN` 상태의 카테고리는 신규 상품의 매핑 대상으로 선택할 수 없다.
  - 기존 상품이 매핑된 카테고리가 `HIDDEN`으로 변경되더라도 해당 카테고리 매핑 자체는 삭제하지 않는다.
  - 카테고리의 전시 여부는 Category 모듈의 정책을 따르며, Product의 `HIDDEN` 상태와 독립적으로 관리한다.

- **대표 카테고리 삭제/변경**:

  - 대표 카테고리 매핑을 삭제하려는 경우 다른 매핑 카테고리를 대표 카테고리로 지정해야 한다.
  - 대표 카테고리가 삭제되었거나 더 이상 유효하지 않은 경우 저장할 수 없다.
  - 대표 카테고리가 `HIDDEN` 상태가 된 경우 상품의 대표 카테고리를 다른 `DISPLAY` 카테고리로 변경할 수 있도록 안내한다.

### 2.3 가격 및 할인 정책 (Pricing & Discount)

- **기본가 (`base_price`)**:
  숫자 입력 (필수, 0원 이상).

- **할인 적용 여부**:
  스위치 토글 (기본 `OFF`).

- **할인 정책 설정 (토글 ON 시 활성화)**:

  - **할인 유형 (`discount_type`)**:

    - `PERCENT` [정률 %]
    - `FIXED` [정액 원]

  - **할인값 (`discount_value`)**:

    - 정률: `1 ~ 99` 정수
    - 정액: 기본가 미만의 금액

  - **할인 기간 (`discount_start_at`, `discount_end_at`)**:

    - 시작일시와 종료일시를 지정할 수 있다.
    - 기간을 지정하지 않은 경우 상시 할인으로 처리한다.

- **실시간 예상 판매가 Live Preview**:

  - 기본가와 할인 정책을 입력하면 최종 판매가를 실시간 계산하여 표시한다.
  - 할인율도 함께 계산하여 표시한다.
  - 최종 판매가는 서버에서도 동일한 규칙으로 재계산하여 검증한다.
  - 클라이언트에서 계산된 판매가를 신뢰하지 않는다.

---

### 2.4 SKU 및 옵션 매핑 (SKU & Option Link)

> Product 모듈은 SKU의 재고 수량을 수정하지 않는다.

- **옵션 사용 여부**:

  - 스위치 토글로 단일 상품과 옵션 상품을 구분한다.

- **SKU 연동 모달**:

  - 재고 모듈에 등록된 SKU 데이터를 검색하고 선택할 수 있다.
  - 검색 조건:

    - SKU 코드
    - 원천 자재명
    - 재고 수량

- **SKU 선택 정책**:

  - 상품에서 사용할 SKU를 선택하여 옵션 조합에 매핑한다.
  - 동일 SKU를 허용할지 여부는 SKU 중복 매핑 정책에 따른다.
  - 하나의 옵션 조합에는 하나의 원천 SKU를 매핑한다.

- **옵션 매핑 테이블**:

  | 항목 | 설명 |
  |---|---|
  | 옵션명 | 예: 색상, 사이즈 |
  | 옵션값 | 예: Red, Blue / S, M, L |
  | 옵션별 추가금 (`surcharge`) | 기본 판매가에 추가되는 금액 |
  | 매핑 SKU (`sku_id`) | 원천 재고 SKU ID |
  | 현재 원천 재고 | Read-Only |
  | 재고 상태 | 정상 / 재고 임박 / 품절 등 Read-Only |

- **재고 수량 수정**:

  - Product Form에서 SKU의 원천 재고 수량을 직접 수정할 수 없다.
  - 재고 수량은 재고 모듈에서 관리한다.
  - 주문에 따른 재고 차감 및 복구는 Order 모듈에서 처리한다.

- **재고 0 SKU 매핑**:

  - 현재 재고가 `0`인 SKU도 상품에 매핑할 수 있다.
  - 해당 SKU에는 `[원천 품절]` 상태를 표시한다.
  - 상품 전체의 판매 가능 여부는 상품 상태 및 전체 SKU 재고 상태 정책에 따라 결정한다.

---

### 2.5 이미지 및 상세 설명 (Images & Description)

- **대표 이미지 (`main_image_url`)**:

  - 1개 필수.
  - 드래그 앤 드롭 파일 업로드 지원.
  - 권장 규격: `1000x1000px`
  - 허용 형식: `JPG / PNG / WEBP`
  - 최대 크기: `5MB`

- **추가 이미지 (`sub_image_urls`)**:

  - 최대 10개.
  - 드래그 앤 드롭 업로드 지원.
  - 이미지 순서 변경(Reorder) 지원.

- **상세 설명 (`description`)**:

  - WYSIWYG 또는 Markdown 에디터 제공.
  - 에디터 내 이미지 첨부 지원.
  - 이미지 업로드 시 CDN URL을 반환받아 상세 설명에 삽입한다.
  - HTML/Markdown 저장 형식은 프로젝트의 콘텐츠 정책에 따른다.

---

### 2.6 하단 고정 액션 바 (Sticky Footer)

- 화면 하단에 Sticky Action Bar를 제공한다.

- **[취소]**:

  - 변경 사항이 없는 경우 즉시 목록 페이지로 이동한다.
  - 변경 사항이 있는 경우 Dirty Check Confirm Modal을 출력한다.

  > "저장되지 않은 변경사항이 있습니다. 정말 나가시겠습니까?"

- **[저장]**:

  - Client Validation 수행 후 API 요청을 전송한다.
  - 서버에서도 동일한 비즈니스 규칙을 검증한다.
  - 저장 성공 시 `/admin/products`로 이동한다.
  - 저장 중에는 버튼을 비활성화하고 Spinner를 표시한다.

- **임시 저장**:

  - 현재 상품 모듈에서는 임시 저장 기능을 제공하지 않는다.
  - 별도의 Draft 상태 및 Draft 저장 정책이 정의되는 경우 추후 별도 기능으로 추가한다.

## 3. 폼 유효성 검사 규칙 (Form Validation Rules)

| 필드 | 검증 조건 | 오류 발생 시 에러 메시지 |
|---|---|---|
| **상품명** | 필수 입력, 1~100자 | "상품명을 입력해주세요. (최대 100자)" |
| **카테고리** | 최소 1개 이상 매핑 | "최소 하나의 카테고리를 선택해야 합니다." |
| **대표 카테고리** | 매핑된 카테고리 중 정확히 1개 지정 | "대표 카테고리를 선택해주세요." |
| **기본가** | 필수 입력, 0 이상의 정수 | "올바른 기본가를 입력해주세요." |
| **할인율 (%)** | 정률 선택 시 1~99 범위의 정수 | "할인율은 1%에서 99% 사이여야 합니다." |
| **할인가 (원)** | 정액 선택 시 기본가보다 작은 금액 | "할인 금액은 기본가보다 작아야 합니다." |
| **할인 기간** | 종료일시가 시작일시보다 미래 시점 | "할인 종료 일시는 시작 일시보다 이후여야 합니다." |
| **옵션 SKU** | 옵션 사용 시 모든 옵션 조합에 SKU 매핑 필수 | "모든 옵션 조합에 원천 SKU를 매핑해주세요." |
| **대표 이미지** | 1개 필수 등록 | "대표 이미지를 최소 1개 이상 등록해주세요." |
| **SOLD_OUT 상태** | 수동 상태 설정 가능 | 별도 오류 없음 |
| **삭제/비활성 카테고리** | 유효하지 않은 카테고리 매핑 불가 | "사용할 수 없는 카테고리입니다." |

## 4. API 연동 매핑 (API Interface Mapping)

| UI 이벤트 / 액션 | HTTP Method & Endpoint | Request Payload / Params | 비고 |
|---|---|---|---|
| **수정 데이터 조회** | `GET /api/admin/products/:id` | `params: { id }` | 수정 페이지 진입 시 기존 상품 정보 조회 |
| **원천 SKU 검색** | `GET /api/admin/skus` | `query: { keyword, page, limit }` | SKU 매핑 모달에서 검색 |
| **신규 상품 등록** | `POST /api/admin/products` | `CreateProductPayload` | 상품 기본 정보, 가격/할인, 카테고리, 옵션, 이미지 저장 |
| **상품 정보 수정** | `PUT /api/admin/products/:id` | `UpdateProductPayload` | 상품 정보 및 카테고리/옵션 수정 |
| **이미지 업로드** | `POST /api/admin/assets/upload` | `multipart/form-data` | 업로드 후 CDN URL 반환 |
| **카테고리 조회** | `GET /api/admin/categories/tree` | - | 상품 등록/수정 시 카테고리 선택 |
| **SKU 상세/재고 조회** | `GET /api/admin/skus/:id` | `params: { id }` | 현재 원천 재고 Read-Only 조회 |

> 상품 등록 및 수정 시 SKU는 상품 옵션에 매핑하며, 원천 재고 수량 자체는 변경하지 않는다.

> 원천 재고의 실제 차감 및 복구는 Order 모듈에서 처리한다.

## 5. 상태 및 비즈니스 정책 (Status & Business Policy)

### 5.1 `DISPLAY`

- 쇼핑몰 전시 대상 상품이다.
- 상품의 판매 가능 여부는 상품 상태와 SKU 재고 상태를 함께 판단한다.

### 5.2 `HIDDEN`

- 상품의 전시를 차단한다.
- 원천 재고와 독립적으로 관리한다.
- 재고가 증가하거나 감소하더라도 자동으로 `DISPLAY`로 변경하지 않는다.

### 5.3 `SOLD_OUT`

- 상품의 구매를 차단한다.
- 원천 재고가 0이 된 경우 시스템에 의해 자동 전환될 수 있다.
- 어드민 관리자가 수동으로 설정할 수도 있다.
- 수동으로 `SOLD_OUT` 처리한 상품은 재고가 증가하더라도 자동으로 `DISPLAY`로 복구하지 않는다.
- 자동 품절과 수동 품절을 구분해야 하는 경우 별도의 상태 변경 이력 또는 메타데이터를 기록할 수 있다.

### 5.4 재고와 Product의 관계

- Product는 SKU와 상품의 관계를 정의한다.
- Product는 SKU의 현재 재고를 조회할 수 있다.
- Product는 SKU의 재고 수량을 직접 변경하지 않는다.
- 주문 완료에 따른 재고 차감은 Order 모듈에서 처리한다.
- 주문 취소/환불 등에 따른 재고 복구 역시 Order 모듈의 재고 처리 정책에 따른다.

## 6. 예외 처리 및 UI/UX 피드백 (Exception Handling)

1. **원천 SKU 재고 부족/품절 매핑 시**:

   - 재고가 `0`인 SKU도 상품에 매핑할 수 있다.
   - 해당 옵션에 `[원천 품절]` 태그를 표시한다.
   - SKU의 재고 수량은 Product Form에서 수정하지 않는다.

2. **저장 처리 중 네트워크 오류**:

   - 저장 버튼 내 Spinner를 노출한다.
   - 저장 버튼을 비활성화하여 중복 요청을 방지한다.
   - 저장 실패 시 토스트를 출력한다.

   > "저장에 실패했습니다. 잠시 후 다시 시도해주세요."

3. **서버 Validation 실패**:

   - 서버에서 반환된 필드별 Validation 오류를 해당 입력 필드 하단에 표시한다.
   - 클라이언트 Validation을 통과했더라도 서버 Validation을 반드시 수행한다.

4. **동시 수정 충돌**:

   - 수정 시 상품의 `version` 또는 `updated_at` 등을 이용하여 Optimistic Lock을 적용할 수 있다.
   - 다른 관리자가 먼저 상품을 수정한 경우 저장을 거부하고 최신 데이터가 존재함을 안내한다.

   > "다른 관리자에 의해 상품 정보가 변경되었습니다. 최신 정보를 확인해주세요."

5. **이미지 업로드 실패**:

   - 업로드에 실패한 이미지는 상품 저장 대상에서 제외한다.
   - 이미지 업로드 실패 사실을 사용자에게 표시한다.

   > "이미지 업로드에 실패했습니다. 다시 시도해주세요."

6. **작성 중 페이지 이탈 방지 (Dirty Check)**:

   - 폼 입력값이 변경된 상태에서 브라우저 뒤로가기, 타 메뉴 이동 등의 이탈이 발생하면 경고 Confirm Modal을 출력한다.
   - 저장 완료 후에는 Dirty 상태를 해제한다.

7. **삭제된 상품 수정 접근**:

   - `DELETED` 상태의 상품은 일반 수정 기능을 제한한다.
   - 수정 페이지 접근 시 삭제 상태임을 안내하고 저장 기능을 비활성화한다.

8. **유효하지 않은 카테고리**:

   - 삭제되었거나 사용 불가능한 카테고리가 기존 상품에 매핑되어 있는 경우 해당 카테고리를 별도로 표시한다.
   - 유효하지 않은 대표 카테고리가 존재하는 경우 저장 전에 새로운 대표 카테고리를 지정하도록 요구한다.
