[상품 시스템 로직 및 기능 설계 문서]

1. 시스템 개요

본 시스템은 사용자에게 상품을 효율적으로 노출하는 '상품 보기(조회) 시스템'과, 관리자가 상품 및 UI 노출 방식을 제어하는 '상품 관리 시스템'으로 구성됩니다. 특히 재사용성이 높은 '상품 간략 블록(2번째 블록)'의 유연한 제어 및 관리에 초점을 맞춥니다.


---

2. 상품 보기 (조회 시스템 로직)

가. 상품 나열 블록 로직 (1번 블록)
- 목적: 메인 페이지 및 카테고리/목록 페이지에서 전체 상품 리스트를 노출합니다.
- 핵심 로직:
  1) 조건별 목록 조회: 카테고리, 검색어, 정렬 조건(최신순, 인기순, 가격순)에 따라 상품 목록을 요청합니다.
  2) 페이징 처리: 데이터 부하를 줄이기 위해 페이지네이션 또는 무한 스크롤 방식을 적용합니다.
  3) 노출 상태 검증: 관리 시스템에서 '노출' 상태로 설정된 상품만 필터링하여 반환합니다.

나. 상품 간략 표기 블록 로직 (2번째 블록 - 공통 재사용 컴포넌트)
- 목적: 메인 페이지, 목록 페이지, 추천 상품, 관련 상품 등 다양한 위치에서 재사용되는 요약 블록입니다.
- 핵심 로직:
  1) 컴포넌트 데이터 바인딩: 상품 ID를 전달받아 해당 상품의 필수 요약 정보(대표 이미지, 상품명, 판매가, 할인가)를 바인딩합니다.
  2) 배지/태그 노출 처리: 관리자가 설정한 뱃지/태그 정보(NEW, BEST, SALE, MD추천 등)를 조회하여 이미지 상단 또는 제목 옆에 표시합니다.
  3) 배치 조회(Batch Fetch): 여러 개의 2번 블록이 한 화면에 노출될 경우, ID 목록을 묶어서 한 번의 API 호출로 요약 정보를 가져와 성능을 최적화합니다.
  4) 네비게이션 이벤트: 블록 클릭 시 전달된 상품 ID를 기반으로 상세 페이지(3번 블록)로 이동합니다.

다. 상품 상세 포스트 블록 로직 (3번 블록)
- 목적: 상품의 전체 상세 정보 및 포스트(본문)를 노출합니다.
- 핵심 로직:
  1) 단건 상세 조회: URL 또는 전달받은 상품 ID로 서버에 전체 상세 데이터를 요청합니다.
  2) 상세 콘텐츠 렌더링: 상품 기본 정보, 옵션 목록, 재고 상태, 상세 설명 포스트(텍스트/이미지/HTML)를 구성합니다.
  3) 예외 처리: 존재하지 않거나 '숨김/삭제' 처리된 상품 ID 접근 시 '판매 중단 또는 존재하지 않는 상품' 안내를 반환합니다.

3. 상품 관리 (관리자 시스템 로직)

가. 기본 상품 CRUD 로직
- 목적: 상품의 원천 데이터를 등록, 수정, 삭제(숨김)합니다.
- 핵심 로직:
  1) 상품 등록: 상품명, 카테고리, 기본 가격, 옵션, 재고, 대표 이미지, 상세 포스트 내용을 저장합니다.
  2) 상품 수정: 기존 상품 정보 및 상세 포스트 내용을 업데이트합니다.
  3) 상품 삭제 및 숨김(Soft Delete):
     - 서비스 특성상 데이터 완전 삭제 대신 '노출 여부(is_visible)' 플래그를 OFF로 변경하거나 '숨김/삭제' 상태값을 업데이트합니다.
     - 숨김 처리된 상품은 사용자 화면(1, 2, 3번 블록)의 조회 로직에서 자동으로 제외됩니다.

나. 2번 블록(간략 표기 블록) 전용 전시 관리 로직
- 목적: 다양한 페이지에 재사용되는 2번 블록의 노출 상태, 순서, 태그를 정밀하게 제어합니다.
- 핵심 로직:
  1) 노출 여부 제어: 
     - 전체 시스템에서의 노출 여부 외에도, 특정 구역/페이지별 2번 블록 노출 활성화 상태를 제어합니다.
  2) 전시 순서 관리 (Display Order):
     - 메인 페이지나 추천 영역 등 특정 전시 구역에 2번 블록들이 노출될 순서 번호(display_index)를 부여 및 수정합니다.
     - Drag & Drop 또는 순서 번호 직접 입력 방식으로 우선순위를 재정렬합니다.
  3) 태그 및 배지 관리 (Tag/Badge Management):
     - 상품별로 표시될 태그(예: NEW, BEST, HOT, MD'S PICK 등)를 다중 선택 또는 직접 입력하여 지정합니다.
     - 태그 노출 기간 설정(예: 등록 후 14일간 NEW 태그 자동 노출 후 소멸 등) 조건부 로직을 포함할 수 있습니다.

4. 데이터베이스 및 API 구조 설계 방향 (요약)

가. 주요 엔티티(테이블) 구성
- Product (상품 원천 정보: ID, 상품명, 가격, 상태, 상세포스트 등)
- Product_Display_Setting (전시/2번블록 관리 정보: 상품ID, 전시구역ID, 노출여부, 우선순위, 태그목록)

나. 주요 관리자 API
- POST /admin/api/v1/products (상품 등록)
- PUT /admin/api/v1/products/{id} (상품 수정)
- PATCH /admin/api/v1/products/{id}/status (상품 숨김/삭제 처리)
- PUT /admin/api/v1/display/blocks (2번 블록 노출 순서, 태그, 노출 여부 일괄 업데이트)
